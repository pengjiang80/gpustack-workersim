# WorkerSim 0.1.3

Start simulated Workers with the same `docker run` command GPUStack shows under
**Clusters → Add Worker**: replace the image, delete `--runtime`, and append the fleet
size and hardware preset.

## Compatibility

| Component | Version |
|---|---|
| WorkerSim product/package | **0.1.3** |
| Supported GPUStack Server / Worker protocol | **2.3.1** |
| Protocol source commit | `458030e88718ce47bd31f7cdee9cbc8994a6760b` |
| Release tag | `v0.1.3-gpustack2.3.1` |

## GPUStack Add Worker command

```bash
sudo docker run -d --name workersim \
  -e "GPUSTACK_TOKEN=<cluster-token>" \
  --restart=unless-stopped --privileged --network=host \
  --volume gpustack-data:/var/lib/gpustack \
  gpustack/workersim:0.1.3 \
  --server-url http://<server> --worker-ip <host-ip> \
  --workers 20 --profile h100-80gb
```

- Accepts `GPUSTACK_TOKEN` (or `--token`), `--server-url`, `--worker-ip`,
  `--advertise-address`, `--data-dir`, `--worker-port`, `--worker-metrics-port` and
  `--kv-transfer-ifname`. `--worker-name` becomes the Worker name prefix (default
  `<hostname>-sim`). Other native flags are logged and ignored.
- The Worker address is detected from the route to the Server when `--worker-ip` is
  omitted.
- Identities persist in the `gpustack-data` volume under `workersim/`; other files in
  the volume are never changed.

## Fleet size and hardware presets

- `--workers N` and `--profile NAME`; `--list-profiles` prints the presets built into
  the image (B300, H100, A800, RTX 4090, Ascend 910B4), each with a typical host shape.
- Per-field overrides: `--gpus-per-worker`, `--gpu-name`, `--gpu-memory-gib`,
  `--cpu-cores`, `--memory-gib`, `--disk-gib`, `--label`, `--nvlink-domain-workers`,
  `--model-rps`.
- Mixed fleets without YAML: repeatable `--group workers=10,profile=b300-288gb,gpus=4`.
- Every option is also a `WORKERSIM_*` environment variable (`WORKERSIM_GROUPS` uses `;`
  between groups).
- `--dry-run` prints the resolved fleet, addresses and ports.

## Automatic host port setup

With `--privileged --network=host`, as in GPUStack's command, WorkerSim adds its API,
metrics, control and inference ports to the host's `ip_local_reserved_ports` at each
start, preserving existing entries. It widens the automatic source-port range to
10240–65535 only when fewer than 20000 source ports would remain. It is not
persisted across reboots. Without privileges the fleet starts and logs that ports were
not reserved. `--no-reserve-ports` disables the step.

The container starts as root only for this step, then drops to UID 10001 before
contacting the Server. Compose and YAML-based runs also drop to UID 10001.

## Compatibility notes

The Compose/YAML workflow is unchanged. Flags can be combined with `--config`; flags
override the file.

## Validation

Regression tests cover native argument mapping, presets and overrides, environment
variables, mixed groups, invalid input, port-range merging and widening, and a fleet
registering through the native-style arguments against the protocol fixture.
