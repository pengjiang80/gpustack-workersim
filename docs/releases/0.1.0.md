# WorkerSim 0.1.0

## Compatibility

| Component | Version |
|---|---|
| WorkerSim product/package | **0.1.0** |
| Supported GPUStack Server / Worker protocol | **2.3.1** |
| Protocol source commit | `458030e88718ce47bd31f7cdee9cbc8994a6760b` |
| Release tag | `v0.1.0-gpustack2.3.1` |

The product version is independent of the GPUStack version. This starts the public
0.1 product series; earlier 0.4.x development tags remain available. Other Server
versions require separate compatibility validation. No Server or UI changes.

## Changes

- Configure up to **1000 Workers / 8000 B300 devices** with eight cards per Worker.
- Default to **20 model ports per Worker**. A shared-IP fleet uses API
  `20100–21099`, monitoring `21100–22099`, and model pools `40000–59999`.
- Share the HTTP transport while preserving separate Worker credentials/sessions.
  The pool has capacity for two persistent event watches per Worker and ordinary
  API requests. Model-instance and model-file watches remain independent.
- Bound concurrent starts with `simulation.registration_concurrency` (default 8).
  Slower Servers apply backpressure to the local queue before HTTP timeouts start.
  A registration rate alone does not limit outstanding requests.
- Bound ordinary REST requests and event-watch handshakes to 16 across the fleet
  with `server.request_concurrency`. Established streams release the quota, so
  all 2000 watches stay connected while preserving capacity for heartbeat/status.
- Add a 1000-Worker example, Linux port-reservation options, and rejection of
  overlapping custom port blocks.
- Keep README compatibility information in Releases, with separate product and
  GPUStack compatibility labels on Docker images.

## Upgrade

Back up the identity volume and keep Worker names and group ordering. Change any
explicit metrics base of `20200` to `21100` before growing past 100 Workers. Custom
port settings are retained: explicitly configured 64-port pools still use 64,
and cannot hold 1000 distinct blocks on one IP. For the new layout, set
`instance_port_start: 40000`, `instance_port_end: 40019`, and omit
`instance_port_stride`. Update host reservations using
`sudo python3 scripts/configure_port_reservations.py --workers 1000 --apply`.
Existing reserved ranges are retained. This can change model endpoints after a
restart; use GPUStack's normal reconciliation and check affected test models.

Keep `nofile=65536` and use Linux host networking. Node count does not guarantee
scheduler throughput. Twenty ports can constrain complex PD/distributed layouts
or high per-node replica counts; allocate a larger block with fewer nodes or
separate IPs/hosts when needed.

## Images

```bash
docker pull gpustack/gpustack-workersim:0.1.0
# Explicit GPUStack compatibility pin:
docker pull gpustack/gpustack-workersim:0.1.0-gpustack2.3.1
```

Both tags refer to the same linux/amd64 build. Historical development tags are
unchanged. The publishing workflow checks source/tag consistency and pulls the
published image by digest to verify `--version` before creating the Release.

## Validation

The suite includes 1000 independently authenticated Workers, 8000 GPU inventory
entries, 2000 event watches, heartbeat reports, identity persistence, assignments
at both ends of the port map, allocation cleanup, and availability changes.
These protocol-fixture tests do not run the GPUStack scheduler. The separate
`Original Server scale acceptance` workflow exercises the original Server,
native inventories, monitoring endpoints, and a small 2→1→0 replica scenario.
Results and measurement boundaries will be recorded after acceptance completes.
