# demo2 Ascend 910B4 模拟集群

在 http://demo2.gpustack.cn:8080 选择 `workersim-910b4` 集群（ID 4）。配置为 3 台服务器，每台 8 张 Ascend 910B4，每卡按需求模拟 64 GiB，总共 24 张卡、1536 GiB（1.5 TiB）显存。

Worker 名称为 `sim-910b4-001` 至 `sim-910b4-003`。设备上报 `vendor=ascend`、`type=cann`、`arch_family=Ascend910B4`，不填写 CUDA compute capability。字段命名依据 [GPUStack Runtime 设备类型定义](https://github.com/gpustack/runtime/blob/main/gpustack_runtime/detector/__types__.py) 及 [Ascend 检测实现](https://github.com/gpustack/runtime/blob/main/gpustack_runtime/detector/ascend.py)。驱动、CANN 版本和功率为合成测试值。

新集群使用独立的 `gpustack-workersim-demo2-910b4` 容器和 `gpustack-workersim:0.4.5` 镜像，身份、配置与注册令牌保存在 `/opt/gpustack-workersim-demo2-910b4`。容器使用 `unless-stopped` 重启策略。B300 集群继续运行其原有 0.4.4 容器。

Worker API 使用 20400–20402，监控使用 20500–20502，控制接口使用本机 20399，模型端口池使用 43200–43391。监听地址为 Docker 桥接地址 `172.17.0.1`。这些端口与 B300 集群分开，系统端口预留范围扩展为 40000–43391。

```bash
sudo docker logs --tail 100 gpustack-workersim-demo2-910b4
sudo docker restart gpustack-workersim-demo2-910b4
```

无密钥模板见 `configs/demo2-3-910b4.yaml`。`scripts/demo2_ascend.py prepare` 生成对应集群配置与私有令牌文件；`verify` 通过公开 API 检查三节点、24 张 64 GiB 设备、两路 watch、24 条 Prometheus 设备监控序列及原有 B300 配置。验收结果保存在 `outputs/demo2-910b4-20261117/acceptance.json`。
